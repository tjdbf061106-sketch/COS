# 샴푸 물성·신규 원료 편입 연구 — 개선본 v1

네 가지 개선 사항을 **별도 앱·검증 도구·개정 프로토콜**에 반영하고, 입력 표현 비교와 모의 신규 원료 편입 실험을 수행했습니다. 기존 `shampoo_physics/app.py`는 보존했습니다. 개선 기능은 **이 폴더의 `app.py`**에서 실행합니다.

먼저 [결과 보고서](report.html), [Word 결과 보고서](docs/연구결과_및_다음우선순위.docx), [개정 프로토콜](docs/신규원료_편입_프로토콜_개정안.docx)을 확인하세요. 보고서의 그래프는 `results/*.png`로도 저장했습니다.

## 반영 사항

- 실제 신규 자료의 처방·제조 배치·측정 ID·동일 조성을 연결해 A 개발/B 최종 평가로 분리하고 해시를 잠급니다. 관련 기록이 양쪽에 걸치지 않도록 연결 그룹 전체를 이동합니다.
- INCI나 SMILES를 기존 상용 원료의 확인 근거로 자동 대체하지 않습니다. 외부 원료는 공급사·등급·로트의 확인 기록을 대조하며 현재 실제 외부 승인 목록은 비어 있습니다.
- 같은 원료 조합의 관측 처방들이 이루는 **공동 조성의 볼록껍질**을 검사합니다. 단일 관측점에서 농도를 바꾼 경우, 조합이 없는 경우, 공동 범위 밖인 경우 수치를 보류합니다. 기하학적 지지를 검증된 오차범위로 표현하지 않습니다.
- 점도·탁도는 **실측 안정·해당 물성 측정** 자료로 별도 지지 영역을 검사합니다. 높은 안정성 점수만으로 회귀 출력을 허용하지 않습니다.
- 클래스별 표본 수 정밀도 시나리오와 통과 판정기를 추가했습니다. 실제 허용오차·목표가 미설정이거나 독립성이 미확인이면 `HOLD`입니다. 임의 합격 기준을 만들어 자동 등록하지 않습니다.

## 새 비교 결과

양성=안정, 임계값=0.5. 아래는 같은 그룹 분할 3회의 평균입니다. 네 지표를 함께 해석하고 민감도·특이도 균형을 봅니다.

| Extra Trees 입력 | Sensitivity | Specificity | MCC | ROC-AUC |
|---|---:|---:|---:|---:|
| 기존 18개 투입량 | 0.546 | 0.870 | 0.445 | 0.802 |
| 61개 보강 입력 | 0.601 | 0.877 | 0.503 | 0.827 |

트리 모델은 양쪽 탐지율이 개선됐지만 안정 제형의 약 40%를 여전히 놓칩니다. 선형 모델은 입력 보강으로 두 클래스의 균형이 일관되게 좋아지지 않았습니다. 전체 비교·분할 SD·회귀 결과는 보고서와 CSV에 있습니다. 개선 모델을 자동 채택하거나 앱의 저장 모델을 교체하지 않았습니다.

18개 원료×3회 분할의 모의 편입에서 개발 조합을 0/4/12/전체로 추가했습니다. 새 원료 최종 평가와 기존 원료 유지 평가를 고정했고 매번 처음부터 학습했습니다. 적은 자료를 추가했을 때 성능이 떨어지는 경우가 있었으며, 전체 추가로 MCC가 올라가도 민감도와 특이도가 모두 좋아지는 것은 아니었습니다. 4그룹은 4개 처방과 같지 않습니다. 실제 배정 수는 `onboarding_allocation.csv`에 있습니다.

확신도 필터는 남은 예측의 오류율을 낮추지만 안정 제형을 더 많이 제외했습니다. 전체·클래스별 예측 비율을 함께 보존했습니다. 결과를 보고 최적 필터를 골라 앱에 배포하지 않았습니다.

**학술제의 핵심은 앱 시연보다 원료 변경 시의 데이터 효율·균형·보류 정책을 검증하는 비교 연구로 잡는 것이 타당합니다.** 다음 우선순위는 같은 추가 자료 예산에서 무작위 선택과 농도·조합 다양성 기반 선택을 비교하는 것입니다. 실제 신규 원료 1종의 독립 실증이 가능하면 가장 큰 한계를 직접 보완할 수 있습니다. 현재 결과는 내부·후향적 비교이며 연구의 독창성이나 학술제 평가 결과를 보장하지 않습니다.

## 실행

현재 폴더에서 실행합니다. 원래 프로젝트의 `../../models/`와 `../../results/candidate_predictions.csv`를 읽으므로 앱을 이 폴더만 떼어 이동하면 해당 참조 자료도 함께 준비해야 합니다. 학습·평가 입력은 `inputs/`에 별도로 보존했습니다.

```powershell
python -m pip install -r requirements.txt
python -m streamlit run app.py --server.address 127.0.0.1 --server.headless true
```

현재 PC의 연구 Python을 사용하는 [run_app.ps1](run_app.ps1)도 제공합니다. 앱은 실측 조회, 공개 원료를 가정한 후보 계산, 실제 원료 확인, 연구 결과로 구성됩니다. 공개 원료 가정 모드는 실제 공급제품·배치가 확인됐다는 뜻이 아닙니다.

```powershell
python -B -m unittest discover -s tests -v
python -B src/verify_revision.py --refit
python -B src/check_ui.py
```

검증기는 모든 저장 지표와 분할을 확인하고 대표 6개 학습 사례를 재현합니다. 전체 학습을 다시 실행한 검사는 아닙니다. 원래 프로젝트의 파일 해시도 대조합니다.

## 실제 신규 자료

1. `templates/new_material_card.json`에 규격 근거를 기록합니다. 원료명·등급 확인과 모델 지원 승인은 별개입니다.
2. `templates/new_experiments.csv`의 식별자·시험조건·원료별 투입량을 채웁니다. `NEW_STOCK_ID_RENAME_REQUIRED`는 실제 새 원료/등급 ID로 바꾸고 `intake_feature_list.json`도 맞춥니다. 신규 원료를 기존 열이나 0%에 숨기지 않습니다.
3. 다음 도구는 식별자가 충분할 때만 A/B 분할을 만들고 기존 잠금 폴더를 덮어쓰지 않습니다.

```powershell
python src/intake_split.py --input new_experiments.csv --feature-list intake_feature_list.json --output-dir new_locked_split
```

식별자는 입력자가 선언한 메타데이터입니다. 실제 제품·시험 독립성이 확인됐다고 자동 판정하지 않습니다. A에서만 모델·전처리·임계값을 개발하고, 고정 후 B를 평가합니다. B로 설정을 바꾸면 새 최종 평가 자료가 필요합니다.

`config/acceptance_criteria.json`은 실제 사용 목적의 허용오차가 아직 없으므로 미설정 상태입니다. `src/acceptance_review.py`는 이를 HOLD로 처리합니다. `sample_size_scenarios.csv`는 독립 단위와 가정한 성능에 대한 정밀도 계산 예시이며 실험 성공 보장·학습 최소 수·검정력 계산이 아닙니다.

## 실험 재현과 파일

`config/research_protocol.json` 및 `analysis_lock.json`은 새 예측 전에 고정했습니다. 기존 데이터·기준선 결과는 이미 검토된 자료이므로 독립 외부검증이나 전향적 사전등록이 아닙니다.

`src/run_benchmark.py --phase all`은 결과가 존재하면 덮어쓰기를 거부합니다. 재실행·새 설정 실험은 별도 버전의 코드·입력·계획·빈 결과 폴더에서 진행합니다. 현재 결과는 `verify_revision.py`로 확인할 수 있습니다.

| 위치 | 내용 |
|---|---|
| `inputs/` | 812개 제형, 원래 분할, 18/61개 입력 및 PK45 시나리오 |
| `config/analysis_lock.json` | 입력·계획·분할·학습 코드 해시 |

보고된 학습 1,566회와 반복 예측 행 수는 독립 실험 표본 수가 아닙니다. 원료별 모의 평가에는 중복 처방이 있고 실제 배치 식별자는 없어, 원료 간 독립성·제조 배치 독립성·외부 일반화를 입증하지 못합니다. 피부·안자극성 라벨·모델 가중치는 물성 학습에 사용하지 않았습니다.
