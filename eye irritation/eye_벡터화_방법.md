# eye 성분조성 벡터화 방법

입력 `1주차/eye_filtered.csv` (1,219행) → 출력 `2주차/eye_vectorized.csv` (849행 × 500열)
재현 스크립트 `build_eye_vectorized.py` · 검증 로그 `eye_vectorized_QC.txt`

---

## 0. 왜 벡터화가 필요한가

원본은 **1행 = (제형 × 활성성분)** 구조입니다. 성분이 3개인 제형은 3행으로 복제돼 있고, 그 3행에 **같은 라벨이 3번** 붙어 있습니다.

**변환 전** (Callisto Xtra, 3행)

| record_id | 성분 | CASRN | 함량% | EPA |
|---|---|---|---:|---:|
| eye_irritation_380 | Atrazine | 1912-24-9 | 34.3 | 3 |
| eye_irritation_381 | Mesotrione | 104206-82-8 | 5.36 | 3 |
| eye_irritation_1333 | (이름 없음) | (없음) | 0.7 | 3 |

이대로 학습하면 같은 제품이 3번 들어가는 **라벨 중복 누수**입니다. 모델링 단위는 성분이 아니라 제형이니까요.

**변환 후** (1행)

| row_id | cas_1912-24-9 | cas_104206-82-8 | … | known_pct | unknown_pct | undeclared_pct | epa_class |
|---|---:|---:|---|---:|---:|---:|---:|
| EyeIrritation6pack_PID186 | 34.3 | 5.36 | 0 | 39.66 | 0.7 | 59.64 | 3 |

성분을 세로로 쌓은 걸 **가로 벡터로 접는 것**이 벡터화입니다.

---

## 1단계 — 행 단위(= 모델링 단위) 확정

| 물질유형 | 원본 | 접은 결과 | 키 |
|---|---:|---:|---|
| 제형 (FIFRA) | 978행 | **608행** | `formulation_id` |
| 단일물질 (ICCVAM·Yamaguchi) | 241행 | **241행** (안 접음) | `record_id` |
| 합계 | 1,219 | **849** | `row_id` |

단일물질을 고유 CAS 단위(183)로 접지 않은 이유: **같은 CAS 의 라벨 통합 규칙은 3주차 사안**입니다. 지금 접으면 그 규칙이 코드 안에 묻혀버립니다. 대신 5단계의 `group_id` 로 묶어서 분할 누수만 먼저 막았습니다.

접기 전에 **라벨이 그 단위 안에서 진짜 상수인지 자동 검증**합니다(EPA / GHS / Draize 각각). 제형 안에서 등급이 갈리면 애초에 접는 전제가 틀린 것이므로, 어긋나면 스크립트가 그 자리에서 멈춥니다. → 불일치 0건 확인.

---

## 2단계 — 성분을 세 종류로 분류

성분 1건이 셋 중 하나로 갑니다.

| 종류 | 건수 | 처리 |
|---|---:|---|
| CAS 있고 함량 있음 | 정상 | 그대로 벡터에 올림 |
| **CAS 없음** | 9 | 컬럼에 올릴 수 없음 → 비율만 `unknown_pct` 로 보존 |
| **CAS 있는데 함량 공란** | 9 | 0 으로 두고 `n_pct_unspecified_ingredients` 로 표시 |

- CAS 없는 9건 = 이름조차 없는 제형 성분 8 + 이름만 있고 CAS 가 없는 단일물질 1(`sucrose fatty acid ester`). 후자는 CAS 를 못 찾은 게 아니라 **단일 CAS 가 존재하지 않는 물질군**이라, 대표 CAS 를 억지로 붙이지 않았습니다.
- 함량 공란 9건은 제형명이 원료명 그대로(`Zoxamide(95_100%)`, `Cyprodinil` 등)여서 원액으로 보이지만, **근거 없이 100 을 넣지 않고** 플래그로만 남겼습니다. 원액 취급으로 정하면 스크립트 상단 스위치(`TREAT_UNSPECIFIED_SINGLE_AS_NEAT`) 한 줄로 전환됩니다.

### 단일물질의 함량은 100 으로 가정

단일물질은 "조성"이라는 개념이 없습니다. 그래서 해당 CAS = 100 으로 두고, **실제 시험농도(10%, 5% 등)는 `test_concentration` 컬럼에 따로** 남겼습니다. 가정값인지 실측 조성인지는 `pct_basis` 컬럼으로 구분합니다 (`assumed_neat_100` / `declared_active`).

이렇게 분리해 둔 덕분에, 시험농도를 벡터값에 반영할지 여부는 **나중에 결정할 수 있습니다**. 처음부터 벡터값에 녹여버리면 "10% 용액"과 "그 물질이 10% 든 제형"이 구분되지 않고 용매 90%는 어디에도 남지 않습니다. (10% 시험 26건이 해당)

## 3단계 — pivot

| 축 | 내용 |
|---|---|
| 행 | `row_id` 849 |
| 열 | `cas_<CASRN>` 454 (제형 성분 274 + 단일물질 183, 중복 3) |
| 값 | 조성 함량 % (0~100) |

규칙 3개:

1. **없는 성분은 0.** 결측이 아니라 "안 들어있음"이 맞습니다.
2. **같은 제형에 같은 CAS 가 두 번 기재되면 합산.** 실제로는 0건이지만 안전장치로 넣었습니다.
3. **제형과 단일물질이 같은 컬럼 공간을 공유.** 그래서 skin·DRD 를 붙일 때 이어붙이고 0 으로 채우면 끝입니다.

열 정렬은 CAS 번호를 숫자 세 블록으로 파싱해서 오름차순으로 했습니다(문자열 정렬하면 `cas_1912-24-9` 가 `cas_98-09-9` 앞에 와서 눈으로 찾기 어려움).

결과 벡터 밀도는 **0.31%** (0 이 아닌 칸 비율).

## 4단계 — 조성합을 셋으로 쪼개기 (재정규화 안 함)

| 컬럼 | 뜻 |
|---|---|
| `known_pct` | CAS 컬럼 합 = **벡터가 설명하는 비율** |
| `unknown_pct` | 이름조차 없는 성분의 비율 |
| `declared_pct_sum` | 위 둘의 합 = 신고된 전체 조성 |
| `undeclared_pct` | 100 − 신고 조성합 = FIFRA 미기재 잔부(불활성·영업비밀) |

**알려진 성분만으로 100% 재정규화하지 않은 것이 이 단계의 핵심입니다.**

Callisto Xtra 는 실제로 `34.3 + 5.36 + 0.7 = 40.36%` 만 공개돼 있고 나머지 59.6% 는 정체불명입니다. 재정규화하면 `85% / 13% / 1.7%` 가 되어 **조성을 전부 아는 제형으로 위장**됩니다. 라벨은 제품 전체에 붙어 있으니, 이 간극 자체가 버릴 수 없는 정보입니다.

제형 608개 기준 `undeclared_pct` **평균 59.8% / 중앙값 70.4%** — 제품 질량의 2/3가 미기재입니다. `unknown_pct` 쪽은 9행·최대 3.0% 뿐이라, 미확인 비율을 AD(적용범위) 신호로 쓰자는 논의의 취지는 실질적으로 `undeclared_pct` / `known_pct` 로 실현됩니다.

### 자동 검증 3종

스크립트가 저장 전에 스스로 확인하고, 틀리면 멈춥니다.

1. 행별 **CAS 컬럼 합 = `known_pct`**
2. **`known_pct` + `unknown_pct` = `declared_pct_sum`**
3. **`declared_pct_sum` = 1주차 원본의 `declared_composition_sum`** (제형 전체)

추가로 조성값이 100 을 넘지 않는지, `row_id` 가 유일한지, 출력 행 수가 단위 개수와 같은지도 확인합니다.

## 5단계 — group_id (동일 조성 묶음)

조성이 완전히 같은 행을 **합치지 않고 묶음 표시만** 합니다.

**키 구성**: 성분별로 `CASRN:함량` 을 만들어 정렬해 이어붙인 문자열 → md5 앞 10자리에 `g` 를 붙임.
- CAS 없는 성분은 `UNK`
- 함량이 공란인 성분은 `NA`
- 예: `104206-82-8:5.36|1912-24-9:34.3|UNK:0.7` → `g...`

원문 키는 `composition_key` 컬럼에 그대로 남겨서 왜 묶였는지 눈으로 확인 가능합니다.

**해시를 쓴 이유**: 파일이 달라도 조성이 같으면 같은 값이 나옵니다. skin·DRD 를 이어붙여도 같은 조성이 **재계산 없이 자동으로 같은 그룹**이 됩니다. (단, `group_size` / `group_label_conflict` 는 파일 단위로 센 값이라 합친 뒤 다시 계산해야 하고, 그 함수를 `load_vectorized.py` 에 넣어뒀습니다)

**함량 공란을 `NA` 로 분리한 이유**: 처음엔 0 으로 접었더니 서로 다른 제형 9개(`Cyprodinil`, `Terbuthylazine`, `Zoxamide` …)가 "똑같이 빈 조성"으로 한 그룹에 뭉쳐서 **없는 중복이 만들어졌습니다.** 키에서 분리해 고쳤습니다.

**결과**

| | 그룹 | 행 |
|---|---:|---:|
| 제형끼리 동일 조성 | 31 | 62 |
| 단일물질 동일 CAS 반복 측정 | 53 | 110 |
| 계 | 84 | 172 |
| 그중 **라벨 충돌** | **14** (제형 8 + 단일물질 6) | 32 |

train/test 분할은 반드시 그룹 단위로 해야 합니다(`group_id` 를 groups 인자로 넘기는 분할기 사용). 안 그러면 거의 같은 데이터가 양쪽에 들어가 성능이 과대평가됩니다.

## 6단계 — 라벨과 파생 플래그

### 라벨 정수화

| 컬럼 | 형식 | 비고 |
|---|---|---|
| `epa_class`, `epa_severity` | nullable 정수 | 결측 49행(전부 단일물질)이 있어도 CSV 에 `1` 로 저장 (`1.0` 아님) |
| `ghs_severity` | nullable 정수 | 클수록 심함(1~4) |
| `ghs_class` | 문자열 | `2A`/`Not classified` 가 섞인 **명목형**이라 정수화 불가 |
| `draize_score` | 실수 | 0.7·1.3 등 비정수 실측값. 연속값이라 스케일 통일 대상 아님 |

EPA 원본은 1이 최악이라 방향이 뒤집혀 있습니다. `epa_severity`(클수록 심함)를 따로 만들어 GHS 와 방향을 맞췄습니다. GHS `2`(2A/2B 미분화) 7행은 `ghs_severity` 를 의도적으로 결측으로 뒀습니다.

> 주의: 저장은 정수로 되지만 **그냥 읽으면 pandas 가 다시 실수로 추론**합니다(결측 때문). `load_vectorized.py` 의 로더를 쓰면 형식이 유지됩니다.

### 단일성분 표시

| 플래그 | 정의 | 건수 |
|---|---|---:|
| `is_single_ingredient` | 성분 1개 | 614 (제형 373 + 단일물질 241) |
| `is_single_named` | 성분 1개 + CAS 있음 | 612 |
| `pseudo_single` | 단일 + `known_pct` ≥ 90 | 360 (제형 **120** + 단일물질 240) |
| `has_vector` | `known_pct` > 0 | 838 (= 11행이 전부 0 벡터) |

제형에서 건진 준단일물질 120개는 1주차 예상치와 일치합니다. 90% 기준선은 스크립트 상단 상수로 빼놨습니다.

### 그 외 남긴 플래그

- `n_uvcb_ingredients` / `uvcb_pct` — 구조식이 존재하지 않는 UVCB 성분(17종) 노출량. 54행(제형 44 + 단일물질 10). 구조 기술자로 갈 때 제외 판단용.
- `n_source_records` / `source_record_ids` — 접기 전 원본 레코드 추적용. 어느 행이 어디서 왔는지 역추적 가능.
- `group_label_conflict`, `casrn_label_conflict` — 라벨 통합 규칙 적용 대상 표시.

## 이 벡터의 한계 (반드시 공유되어야 할 부분)

**`cas_*` 컬럼 자체는 최종 피처가 아닙니다.** 단일물질 행은 사실상 CAS one-hot 이라, 학습에서 본 적 없는 물질에 대한 일반화 능력이 0입니다.

3주차에 `CAS → SMILES → 분자기술자` 로 바꾸고, **여기 담긴 조성 %를 가중치로 써서 제형 기술자를 합성**하는 것이 실제 피처화입니다. 즉 이 파일의 역할은 **그 가중치 행렬**이고, `known_pct` / `unknown_pct` / `undeclared_pct` 는 그 합성이 제품 전체를 얼마나 설명하는지 알려주는 신뢰도 축입니다.
