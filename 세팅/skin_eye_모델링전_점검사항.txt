skin/eye 모델링 넘어가기 전 점검사항 (2026-10-06)

[이미 해결된 것 - 교차검증 완료]

1. 염 제거(salt stripping)
eye팀이 skin 쪽에 "빠졌다"고 알려줬는데, 이미 독립적으로 발견해서 수정 완료한 상태.
두 팀이 계산한 보정값이 완전히 일치함(Abamectin MW 1732->873, LogP 10.4->5.4, 똑같은 숫자).
상호검증된 셈이라 안심해도 됨.

2. sanitizeFrags=True 누락 위험
eye팀이 경고한 "조용히 NaN되는 문제", skin 쪽 descriptor 8개 전부 NaN 없음을 직접 재확인함.
RDKit 버전 차이인지 skin 8개 descriptor가 그 문제에 안 걸리는 건지는 모르겠지만, 결과적으로 안전.

3. Group split 방식 호환성
eye팀이 skin의 MIX-id 그룹핑과 자기네 해시 그룹핑이 ARI=1.0(완전 동일 분할)임을 직접 검증해둠.
트랙별 분리학습이면 문제없음.


[팀 논의 필요 - 새로 드러난 것]

4. eye도 아직 "Mixture vs Chemical" 스코프 미결
9월에 제기됐던 문제가 그대로 남아있음. 지금 eye_vectorized.csv(841행)에
Mixture 606 + Chemical(순물질) 235가 섞여있는데, 라벨 균형이 완전히 반대임.
- Mixture만: 비독성 81% / 독성 19%
- Chemical만: 비독성 42% / 독성 58% (원액이라 당연히 더 독함)
- 섞으면 72%/28%로 뭉개짐
-> 섞을지 Mixture만 쓸지 반드시 결정하고 넘어가야 함.
(skin의 "성분 1개 제형도 formulated product"와는 다른 문제 - Chemical은 아예 원액 단독시험이라 모집단 자체가 다름)

5. 클래스 불균형이 skin과 eye가 완전히 다름
skin은 1:17.8(극심)인데 eye는 Mixture 기준 1:4.3 정도(훨씬 양호).
멀티태스크 loss 가중(alpha*skin + beta*eye) 설계할 때 이 차이를 반영해야 함.
한쪽은 불균형 보정이 훨씬 급한데 똑같은 처방을 쓰면 안 됨.

6. weight_mode=equal_fallback이 eye는 244건(29%)
skin은 10건(1.8%)뿐이었는데 eye는 거의 1/3이 "함량비를 몰라서 균등가중치로 때운" 상태.
feature 신뢰도에 큰 영향 - 모델링 전 심각성 재평가 필요.

7. group_label_conflict 24건(eye) vs 극소수(skin)
동일조성인데 라벨이 다른 경우가 eye가 훨씬 많음.
worst-case 라벨 채택 vs 제외, 처리방침 통일 필요.

8. feature 세트 자체가 다름
skin은 descriptor 8개뿐인데 eye는 8개(공통) + 전체 RDKit 217개 + Morgan FP 2048개(총 2304컬럼).
구조상 문제는 없지만(task별 encoder가 따로니까), 의도한 설계인지 team이 합의한 건지 확인 필요.
eye 모델이 훨씬 고차원이라 과적합 위험/학습 난이도가 skin과 많이 다를 수 있음.


[공통으로 남은 것 - 양쪽 다 동일하게 지적]

- ESOL_LogS <-> LogP 다중공선성(-0.9대): 둘 다 발견, 하나 제거 필요
- 무기물/금속 성분의 일부 descriptor 원천 NaN(Gasteiger 전하 미정의): imputation 말고 결측표시자로 처리 권장
- ESOL 공식 자체가 부정확(eye팀 RMSE 1.3 확인): 절대값 말고 순서정보로만 사용 권장
