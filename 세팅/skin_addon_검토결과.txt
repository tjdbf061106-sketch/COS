skin_addons.ipynb 검토 결과 공유 (2026-10-06)

보내주신 추가 검증 모듈, 실제 skin 데이터로 전부 실행해봤습니다. 결과 요약드립니다.


1. EPI Suite 대조 - 템플릿까지만 만들었습니다

epi_check_template.csv 생성했습니다(30종, LogP 5분위 층화추출, 염 제거 적용 3종 포함).
EPI Suite 값 입력은 GUI 프로그램이라 직접 돌릴 수 없어서, 여기서부터는 사람이 해야 합니다.

하실 일: smiles_for_EPI 컬럼 값을 EPI Suite에 넣고
epi_exp_logKow / epi_KOWWIN_logKow / epi_exp_WS_mgL / epi_WSKOWWIN_WS_mgL
4칸을 채워주세요. 채워서 주시면 상관계수/오차 계산해서 다시 공유드리겠습니다.


2. unknown_pct / undeclared_pct - 걱정하신 버그는 없었고, 넣는 게 좋겠습니다

점검 결과: unknown_pct NaN 0건, undeclared_pct NaN 0건, 합계 100 초과로 클립된 제형 0건.
말씀하신 NaN 전파 시나리오는 우리 skin 데이터에서는 실제로 발생하지 않았습니다.

다만 "메타컬럼을 모델 입력에 넣을지"는 실제로 비교해봤습니다.
- descriptor만(7개): ROC-AUC 0.749 / PR-AUC 0.131
- descriptor + meta(9개): ROC-AUC 0.764 / PR-AUC 0.154 (5개 시드 전부에서 개선)
- meta만(2개): ROC-AUC 0.584 (descriptor 단독보다 낮아서, 메타컬럼이 데이터셋 아티팩트로 전체 신호를 만드는 건 아닌 것으로 보임)

결론: 메타컬럼(unknown_pct, undeclared_pct) 모델 입력에 포함하는 쪽으로 가면 좋을 것 같습니다.


3. 집계방식(wmean/top/max/min) - 아직 검증 못 했습니다

top/max/min 버전이 구현돼 있지 않아서 비교 자체가 불가능했습니다.
소량 성분이 전체 결과를 지배할 수 있다는 우려는 화학적으로 타당한 지적이라고 생각하는데,
실제로 다른 집계방식을 만들어서 비교해보기 전까지는 가설 단계입니다. 다음에 구현해서 확인하겠습니다.


4. comp_group_id 그룹분할 - 검증은 통과했는데, 실제 harness와는 다릅니다

보내주신 grouped_cv()가 매 fold마다 train/test 그룹이 안 겹치는지 자동으로 확인하는데,
에러 없이 통과했습니다(그룹 누수 없음).

다만 지금 실제 모델링에 쓸 harness(modeling/src/splits.py)는
5-fold 교차검증이 아니라 단일 80/20 분할 1회뿐입니다.
보내주신 방식(5-fold x 5시드 = 25회 평가)이 훨씬 안정적인 평가라서,
harness를 이 방식으로 업그레이드할지 팀에서 정해야 할 것 같습니다.
