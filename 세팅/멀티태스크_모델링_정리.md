## 3. 교수님 피드백 — 모델링 방향 전환

**기존 계획(폐기)**: skin/eye 완전 분리된 RF/XGBoost 모델, 4단계 다분류 + 이분류(1~2 vs 3~4) 이중 검증 체계

**신규 채택 방향**:
1. **Multi-task Model**: skin과 eye를 하나의 모델로 통합 학습 — 단, 입력 feature space가 다르므로(270 vs 454차원) "완전히 같은 벡터"가 아니라 **각 task를 독립 인코더로 받아 공통 잠재공간에서 결합**하는 구조(아래 4절 아키텍처 참조)
2. **분류 Loss**: Cross Entropy Loss, **PyTorch로 구현**
3. **Vector 결합**: skin 벡터(인코딩 후) × α + eye 벡터(인코딩 후) × β — 가중합산, α/β는 학습 중 최적화
4. **라벨 단순화**: 4단계 다분류 폐기, **이분류(0=독성없음/1=독성있음) 단일 체계로 통일**
5. 클래스 불균형이 심해 성능이 안 나오면 **1:1 리밸런싱**(언더/오버샘플링) 시도

**리밸런싱 관련 메모**: skin은 544건 중 양성(자극) 29건뿐이라 1:1 맞추면 전체 58건으로 줄어듦 — 데이터 손실이 크므로, 1:1 강제 샘플링은 "최후 수단"으로 두고 먼저 weighted CrossEntropyLoss(class weight) 또는 focal loss를 시도하는 순서를 권장.

## 4. 아키텍처 설계 초안

```
skin_input (270dim, CASRN 함량%)          eye_input (454dim, CASRN 함량%)
        │                                         │
        ▼                                         ▼
  skin_encoder (Linear→ReLU→...)          eye_encoder (Linear→ReLU→...)
        │ → skin_embedding (H dim)                │ → eye_embedding (H dim)
        └──────────────────┬──────────────────────┘
                            ▼
              z = α·skin_embedding + β·eye_embedding   (α, β: learnable scalar)
                            ▼
                    shared classifier head
                            ▼
                 CrossEntropyLoss (2-class: 독성 0/1)
```

- `skin_encoder`/`eye_encoder`는 입력 차원이 달라도 되는 task-specific 레이어 — "skin 따로 eye 따로 모델링하고 나중에 합친다"는 방향과 일치
- H(공통 hidden 차원)는 실험 파라미터, 64~128 정도로 시작 권장
- α, β는 `nn.Parameter`로 선언 후 softmax 정규화(α+β=1 제약)할지, 제약 없이 자유 학습할지는 실험 필요
- 한 샘플이 skin 데이터인지 eye 데이터인지에 따라 해당 encoder만 활성화되는 구조인지(샘플 단위로 skin/eye 중 하나만 존재), 아니면 같은 제형에 skin+eye 데이터가 모두 있는 경우를 가정하는지는 **팀 확인 필요**(현재 ICE 데이터 구조상 skin/eye는 서로 다른 Formulation_ID 집합이라 완전히 겹치는 제형은 드묾 — 이 경우 "결합"의 실제 의미를 다시 정의해야 할 수 있음)

## 5. 열린 질문 (다음 팀 미팅/교수님 확인 사항)
1. ~~skin·eye가 같은 제형(Formulation_ID)을 공유하지 않는데, "가중합산"이 샘플단위 결합인지 loss단위 결합인지~~ → **(A) Hard parameter sharing으로 확정(2026-09-18)**. 근거: 연구 최종목적(④~⑤단계)이 "화장품 제형 1개 조성 → skin/eye 자극성 둘 다 예측"이라 배포 시점엔 조성 1개에서 두 예측이 나와야 함. 현재 ICE 데이터는 skin/eye가 서로 다른 Formulation_ID라 샘플단위로 두 벡터를 더할 짝 자체가 없음(B 불성립). (A)는 skin_encoder/eye_encoder가 각자 데이터로 shared 표현을 함께 학습하고 skin_head/eye_head로 각각 예측 — 두 데이터셋의 "적은 데이터+불균형" 약점을 공유학습으로 보완하는 효과도 있음. 교수님의 "α·skin벡터+β·eye벡터 가중합산"은 **task loss 가중합(`total_loss = α·skin_loss + β·eye_loss`)** 또는 **cross-stitch 방식의 중간표현 혼합**으로 해석해 구현.
2. α/β 학습 방식(scalar vs per-dim vs attention-gate)
3. 클래스 불균형 대응 순서(weighted loss → 그래도 안되면 1:1) 합의
4. eye Mixture 스코프(608 vs 579) 확인 후 최종 학습 샘플 수 확정
5. skin/eye `binary_label` 파생 기준 통일(이미 같은 "Category 1~2 vs 3~4" 기준으로 합의되어 있음, eye에 컬럼만 추가하면 됨)
